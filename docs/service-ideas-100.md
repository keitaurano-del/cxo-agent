## A. 方法論・スコアリング基準

### 良い候補の4条件
1. **エバーグリーン検索需要** — "convert / calculator / free ~ online / how to" 系の恒常的検索意図。流行り廃りが小さい。
2. **作り込める** — ブラウザ完結（client）or 軽バックエンド or AI呼び出しのみ。SDK地雷・重インフラ・法規制を避ける。
3. **広告適性** — 滞在時間・再訪率・PV/セッション・CPM帯（金融/法律/BtoB系は高CPM、汎用ツールは低〜中CPM）。
4. **差別化余地** — 競合が強くても「日本語特化」「UX一点突破」「AI付加」「登録不要・無料」で割り込めるか。

### スコア式（明記）
```
優先度スコア = 検索需要(D) × 作りやすさ(E) × 広告適性(A) ÷ 競合強度(C)   ※各1〜5
```
- D: 5=世界的巨大KW群 / 3=中規模 / 1=ニッチ
- E: 5=client完結・数日 / 3=軽backend or wasm / 1=重AI・重インフラ
- A: 5=高CPM(金融等)＋滞在長 / 3=汎用ツールCPM / 1=単発・低CPM
- C: 5=巨人多数(逆風) / 3=中堅多数 / 1=空白
- 目安: **20以上=有望 / 15前後=条件付き / 10未満=見送り寄り**

### 実装区分の凡例
`C`=client完結（JS/wasmのみ） / `B`=軽バックエンド要 / `AI`=LLM/ML API要
