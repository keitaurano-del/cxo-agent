# タスクボード＆完了フロー再構築（MC-358）設計 v1

2026-08-02 Keita「この手順をターミナルじゃなくてタスクボードに記載して流れていかないように。全体的にタスクボードとタスクを完了する仕組みを再構築してほしい」

## 現状の問題（実測）

1. **台帳の行が肥大化**: TASK_TRACKER.md の1行が数千字のログ塊（例: MC-290）。ステータスが読めない・diffが壊れやすい・並行編集事故の温床。
2. **チャット/ターミナルに流れる情報がある**: Keitaへの手順・依頼がターミナル発言のまま消える（今回の指摘）。
3. **「完了」の定義が曖昧**: DONE の根拠（検証・反映先）が行内ログに埋もれ、棚卸しで毎回掘り直している。
4. **Keita操作待ちの置き場が分散**: blockers.json（機械用）と夜報告（揮発）のみで、常設の人間用ビューが無い。

## 再構築の方針

### 層1: データ構造の分離（正本の再定義）
- `docs/TASK_TRACKER.md` = **1タスク1行のインデックスのみ**（ID/タイトル/優先度/ステータス/担当/次アクション1行/詳細リンク）。
- `docs/tasks/MC-<n>.md` = タスク個票（経緯ログ・検証記録・完了根拠）。行内に溜まっていた長文はここへ移す。
- `data/blockers.json` = 機械用レジストリ（既存・MC-353）。個票から生成。
- 既存の巨大行は**段階移行**: 新規タスクから個票方式、既存の未完タスク（MC-290/313/331/347/351/352/354）は次回更新時に個票へ切り出し。DONE行は年次アーカイブ `docs/archive/TASK_TRACKER-2026H1.md` へ退避し本体を軽くする。

### 層2: Keita操作キューの常設化
- `docs/keita-actions.md`（本日新設・運用開始済）: Keitaにしかできない操作を手順付きで常設。チェックボックスで消し込み。
- Apollo UI: タスクボードに「Keita今日の2分」カードを追加し keita-actions.md を表示（未完のみ・完了ログは折りたたみ）。

### 層3: 完了フローの明文化（Definition of Done）
- DONE 遷移の条件: ①成果物の場所 ②検証方法と結果 ③本番反映有無 を個票に1行ずつ記載してから DONE にする。
- 決裁済み事項は決裁ID（dec-xxx）を個票に記録し、blockers.json から自動消し込み。
- 夜21:30棚卸し（board-audit）は「個票の DoD 記載チェック→インデックス行の同期→blockers.json 再生成→keita-actions.md 消し込み確認」に手順を更新。

### 層4: Apollo ボードUIの同期
- /api/tasks のパーサを「インデックス行＋個票リンク」形式に対応させる（1行が短くなるためパースは簡素化される）。
- ボードのタスクカードから個票 md を開ける導線。
