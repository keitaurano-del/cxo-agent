# MC-365 — Keita待ちの決裁自動ボタン化

- **起票:** 2026-08-03（Keita「一時的なものじゃなくて機能としてほしい」）
- **担当:** Son
- **背景:** 型A（Keita判断待ち）が台帳メモ止まりだと決裁ボタンが立たず放置されがち。8/3にSonが4件を手動投入したが、これを恒久機能化する。

## 実装

blockers.json（board-auditが日次生成）の `next_actor='keita'` エントリを、決裁フロー（/api/decisions）へ自動投入する lazy 同期を backend に追加。

- `server/src/lib/blockerDecisionSync.ts`（新規）: 同期本体。汎用3択（承認して進める/修正・指示あり/保留）で決裁を自動生成。
- `server/src/lib/decisionRequestStore.ts`: `DecisionRequest.taskId` 追加（重複判定キー）＋ `listAllDecisions()` 追加。
- `server/src/decisionRouter.ts`: GET /api/decisions 読み出し時に `applyBlockerSync()`（applyExpiredFallbacks と同じ lazy sweep 流儀・cron依存なし）。
- `server/src/config.ts`: `BLOCKERS_FILE` 追加。

**重複防止:** taskId（旧レコードは title 内の taskId 文字列）で照合し、待ち開始日（blocker.since 00:00 JST）以降の決裁が既にあればスキップ。手動で選択肢を練った決裁（POST /api/decisions/request）が常に優先され、同期は後追い投入しない。棚卸しで blockers.json から待ちが消えれば以後は投入されない。
